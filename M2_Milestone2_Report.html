Section 2: Prompt and Solution Design

2.1 Problem Formulation & Target Users

Undergraduate university students routinely struggle when revising from dense, unstructured lecture slides, handwritten notes, and lengthy lecture transcripts. Standard commercial LLMs frequently hallucinate external details, introduce facts from general pretraining that instructors never covered, format practice questions inconsistently, or produce disjointed answer keys.

SmartStudy AI solves Problem C2 by converting raw lecture notes (PDF or TXT) into a complete, source-grounded study pack comprising three strictly ordered components: (1) an undergraduate-level executive summary, (2) key technical terms and definitions constrained strictly to source notes, and (3) exactly 5 practice questions covering five distinct pedagogical formats (MCQ with distractors, Short Answer, Fill-in-the-Blank, Scenario Application, and True/False with correction), complete with inline answers.

2.2 Prompt Architecture & Model Selection

Rather than dividing the task into chained sub-calls that incur high latency and context fragmentation, SmartStudy AI utilizes one master prompt template featuring comprehensive negative constraints, deterministic fallback definitions, and a silent final self-verification directive.

We deploy Google Gemini 2.5 Flash / Gemini 2.0 Flash via LangChain. Gemini offers a massive context window (over 1M tokens), near-zero inference latency, zero cost for academic experimentation on Google AI Studio, and exceptional adherence to strict negative instructions. LangChain provides clean prompt templating and multi-provider abstraction.

2.3 Progress & Architectural Changes Since Milestone 1

  • Modular Decoupling: Transformed initial scripts into a clean modular package (src/) with dedicated loaders, prompt managers, LLM orchestrators, and output validators.
  • Deterministic Fallback Sentence: Solved term hallucination by forcing the model to emit the exact canonical sentence: "The supplied notes do not define this term in detail." for mentioned but undefined concepts.
  • Automated Structural Rule Engine: Created a 10-point regex validator (src/output_validator.py) running locally without LLM overhead.
  • Side-by-Side Comparison UI: Added a concurrent dual-prompt execution mode in Streamlit to empirically test and demonstrate prompt iterations on identical inputs.

Prompt Template 
You are SmartStudy AI, a study assistant for intermediate undergraduate students.
Your task is to convert the lecture notes provided below into a structured, reliable study pack. Use the supplied lecture notes as your sole factual source.

## 1. Source Grounding
- Use only facts, definitions, and relationships explicitly stated in the supplied lecture notes.
- Do not introduce outside knowledge, unsupported explanations, invented examples, or additional technical concepts.
- If the notes do not contain enough information to support a definition or answer, state that limitation rather than guessing.

## 2. Structure and Top-Level Sections
The output must contain exactly three top-level sections, in this exact order:
1. Summary
2. Key Terms and Definitions
3. Practice Questions
- Do NOT use Markdown tables. Do NOT add a conclusion, preface, notes, or any fourth section.

## 3. Section Specifications
### Section 1: Summary: Summarize all major concepts clearly and concisely.
### Section 2: Key Terms and Definitions: Include only technical terms appearing in notes. If a term is not defined sufficiently, use this exact sentence: The supplied notes do not define this term in detail.
### Section 3: Practice Questions: Generate exactly five questions numbered sequentially:
1. Multiple-choice question (options A, B, C, D with 1 correct answer)
2. Short-answer question
3. Fill-in-the-blank question
4. Scenario-based question
5. True/false question (if False, include source-supported correction in answer)
- Clearly label the answer for each question with "Answer:".

## 4. Silent Final Verification
Before producing the final study pack, silently verify that all 3 sections exist, exactly 5 questions are present in order, and zero unsupported outside facts exist. Do not output this checklist.

Lecture notes:
{lecture_notes}
Template Variables {lecture_notes}: Extracted text from uploaded PDF/TXT or pasted notes
Examples Included 0 (Zero-shot prompt with strict negative constraints)
Output Format Clean Markdown with 3 numbered headings and inline answers

Section 3: Implementation

3.1 What is Built

The prototype is a fully functioning Python web application built on Streamlit and LangChain, featuring modular services in src/ and an automated unit test suite containing 56 passing tests (pytest tests/). It accepts PDF and TXT files, performs automated structural validation, and supports side-by-side prompt experimentation.

3.2 Module Status Table

Module Name File Location What it Does Status Notes
Document Loader src/document_loader.py Extracts text from PDF (PyMuPDF) and TXT files with dual UTF-8 / Latin-1 encoding fallback. Working Robust against scanned, corrupted, and empty files.
Prompt Manager src/prompt_manager.py Dynamically registers, discovers, and binds versioned prompt templates under prompts/. Working Enables hot-swapping prompt templates without modifying code.
LLM Service src/llm_service.py Configures and invokes LangChain chat models for Google Gemini and OpenAI. Working Reads API keys safely via .env without leaking secrets.
Output Validator src/output_validator.py Executes 10-point deterministic structural check on section counts, order, and questions. Working Zero latency; runs locally without additional LLM calls.
Streamlit Web UI app.py Provides user interface, dual-column parallel prompt comparison, and Markdown export. Working Parallel async execution via ThreadPoolExecutor.

4.2 Known Limitations & Next Steps for Milestone 3

  1. Direct Context Passing (No RAG): The prototype passes the entire document directly into the prompt. For multi-chapter textbooks (100+ pages), this will degrade attention. Next Step: Implement a RAG chunking and vector retrieval pipeline for Milestone 3.
  2. Lack of Optical Character Recognition (OCR): The system cannot parse scanned physical notes or image-only slides. Next Step: Integrate Tesseract OCR or multimodal Gemini Vision input.
  3. Absence of Input Noise Classifier (Test T09): The model attempts to summarize random non-academic gibberish. Next Step: Implement a lightweight prompt-based input classification guardrail prior to generation.
