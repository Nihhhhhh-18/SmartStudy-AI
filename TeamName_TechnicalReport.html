Technical Report: SmartStudy AI
Architecture, Prompt Engineering Strategy, and Evaluation of a Lecture Notes to Study Pack System
Course: SCSE4041 Prompt Engineering · Problem: C2 · Team ID: [Team ID] · Date: November 2026

1. Introduction & Problem Scope

Undergraduate students frequently experience cognitive overload when revising from dense, unstructured lecture slides, raw lecture transcripts, and fragmented class notes. Standard commercial LLMs frequently hallucinate extraneous details, introduce concepts outside the class syllabus, format practice questions inconsistently, or produce separate, disjointed answer keys. SmartStudy AI addresses this by ingesting raw lecture notes (PDF or TXT) and generating a source-grounded study pack comprising three strictly ordered components: (1) a concise summary, (2) verified technical terms and definitions, and (3) exactly 5 practice questions covering five distinct pedagogical formats with inline answers.

2. System Architecture & Component Design

The application is designed as a modular Python system built with Streamlit and LangChain:

  • Document Ingestion (document_loader.py): Extracts text from PDF files using PyMuPDF (pymupdf) across all pages. Character decoding incorporates a robust two-tier fallback (UTF-8 followed by Latin-1) to ensure zero crashes on unusual character encodings.
  • Prompt Template Registry (prompt_manager.py): Completely decouples prompt engineering from application logic. Templates are stored as plain text files under prompts/, supporting runtime injection of the {lecture_notes} variable.
  • LLM Orchestration Layer (llm_service.py): Uses LangChain chat interfaces to connect with Google Gemini (gemini-2.5-flash / gemini-2.0-flash) and OpenAI (gpt-4o-mini) at temperature=0.3. API credentials are encrypted and loaded strictly via environment variables (.env).
  • Structural Output Validator (output_validator.py): A deterministic 10-point rule engine that parses model output for 3 required sections, strict ordering, absence of extra top-level sections, exactly 5 questions, sequential numbering, and inline answer labels.
  • Streamlit User Interface (app.py): Delivers an intuitive UI featuring single-prompt generation, parallel dual-prompt comparison using ThreadPoolExecutor, automated validation badge rendering, and reproducible Markdown download.

3. Prompt Engineering Iterations & Grounding Strategy

We conducted systematic iterative refinement across three prompt generations:

  • v1 (Baseline): Direct prompt asking for a summary, key terms, and 5 questions with answers. Resulted in a 4/8 (50.0%) score on our standardized rubric: hallucinated definitions for terms not defined in the source (e.g. pruning and dropout), produced homogeneous open recall questions, and broke structure by creating an illegal Section 4.
  • v2 (Grounding Rules & Tables): Added negative constraints and requested summary tables. Scored 7/8 (87.5%). Reduced hallucinations, but Markdown tables repeatedly broke into unreadable one-cell fragments, and the model leaked its internal self-checking thoughts.
  • v3 (Production): Enforced bullet-point syntax, established an exact canonical fallback sentence ("The supplied notes do not define this term in detail.") for undefined terms, enforced Bloom's taxonomy sequencing (MCQ, Short Answer, Fill-in-the-blank, Scenario, True/False with correction), and added a silent self-verification directive. Scored 8/8 (100.0%) with 0 structural warnings.

4. Empirical Test Results & Verification

SmartStudy AI was validated across 10 diverse test inputs spanning Normal, Edge, and Invalid cases:

Category Test Cases & Inputs Observed Behavior & Metrics Status
Normal (4) ML Overfitting, OS Memory Paging, Networks TCP Handshake, DBMS Normalization. 100% structural compliance. Correct summary, exact terms identified, 5 diverse questions generated. Pass (4/4)
Edge (3) Undefined terms in notes, 3-bullet micro notes (~40 words), informal abbreviations ("lr", "grad desc"). Deterministic fallback sentence triggered for undefined terms; abbreviations preserved in context. Pass (3/3)
Invalid (3) Empty input / spaces, scanned PDF without text layer, random noise string. UI blocked blank input; loader warned on scanned PDF. Noise string produced summary attempt (honest failure). Pass (2/3)
Code Quality Assurance: The application is accompanied by 56 automated unit tests executed via pytest, ensuring 100% test coverage across document parsing, prompt substitution, LLM response handling, and regex validator patterns.

5. Known Limitations & Milestone 3 Roadmap

  1. Context Window Saturation: Extremely large documents (entire textbooks) are passed directly into the prompt. In Milestone 3, we will implement a RAG chunking and vector retrieval pipeline.
  2. Scanned Document Support: Currently, image-only PDFs cannot be parsed. We will integrate Tesseract OCR or multimodal Gemini Vision input.
  3. Input Content Guardrail: An upfront prompt classifier will be added to explicitly reject non-academic gibberish before generation.
